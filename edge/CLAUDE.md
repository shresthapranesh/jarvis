# edge/ — Rust edge in front of Python

Read `README.md` here before changing routing, the worker link, the supervisor, or porting an operation — it has the wire-format contracts and the porting checklist.

- Goal: move jarvis to Rust incrementally so it runs on old, low-RAM hardware. Order work by RAM saved; the kernel stays Python.
- The edge owns :8000: it serves ported GraphQL operations from SQLite, the SPA, the chat page's startup queries (`models`, `todos`, `browserAvailable`), and — while a Python worker is linked — subscriptions, `runningTasks`, stops and run triggers. Everything else is proxied to Python on :8001.
- **Python owns the schema** (`db/engine.py:_migrate`). A GraphQL type is ported whole or not at all.
- Every ported operation is diffed against Python by `tests/test_edge_parity.py`, `test_edge_runs.py`, `test_edge_start.py`, `test_edge_supervisor.py`, `test_edge_schedule.py`. Keep them passing; add to them when porting.
- **Supervisor**: with `JARVIS_WORKER_CMD` set the edge starts Python when a job or proxied request needs it and stops it after `JARVIS_WORKER_IDLE` seconds (default 300) with nothing running, queued, or held.
- **Kernels** (`src/kernels/`): the agent's `ipykernel` processes are the edge's — Jupyter wire protocol over ZMQ (pure-Rust `zeromq`, ipc). Python behind the edge runs `run_cell` through loopback `/internal/kernels/{run,shutdown}` (`core/kernels.py:EdgeKernels`), so a notebook outlives an idle-stopped worker. A port of `core/kernels.py` — a change is made in both; diffed in `tests/test_edge_kernels.py`.
- **Bots** (`src/bots/`): Telegram and Discord run here, not in Python — a message is `start_chat`, the reply follows the run mirror. Python behind the edge starts neither; the Python bots only run when Python stands alone, so a bot change is made in both. Tested against a fake chat service in `tests/test_edge_bots.py`.
- **Scheduler**: the edge fires every schedule. `src/cron.rs` ports APScheduler's `CronTrigger` (DST quirks included) — a change to `core/scheduler.py:_cron` must be made in both. `src/schedule.rs:dispatch` must stay a port of `dispatch_board_tasks`.
- **LLM layer** (`src/llm/`, phase 2b): v1 transcript types, a port of the history shaping and cache layout, and hand-written clients for Gemini, Ollama, Chat Completions (OpenRouter) and Responses (Meta). The agent loop's model calls (`src/agent/`); `--llm-shape` / `--llm-call` drive it alone. `shape.rs` ports `core/messages.py` + `core/context_cache.py`, `compact.rs` ports `apply_per_call_compaction`, `perf.rs` ports `core/perf.py` — a change there is made in both. Diffed against Python in `tests/test_edge_llm.py`.
- **Agent loop** (`src/agent/`, phase 2d; on unless `JARVIS_AGENT_RUNTIME=python`): the chat turns, automation runs and board tasks the edge can serve are queued with `jobs.runtime = 'edge'` (`route.rs`) and claimed here (`queue.rs`, Python's claim plus the runtime condition). Python never claims, reaps or sweeps an edge job; the supervisor ignores them. The loop (`turn.rs`) runs a turn here — prompt as `model_request_node` builds it (`prompt.rs`, a port: change both), `run_cell`, the todo tools and `remember` (`tools.rs`; schemas exported from Python to `tools.json`), retrieval and embeddings (`retrieve.rs`/`embed.rs`, ports of `core/retrieval.py`, `search_memory`, `search_skills`, `search_episodes`, `upsert_memory` — change both), summarizing compaction and episodes (`summarize.rs` + `llm/compact.rs`, ports of `maybe_compact`/`record_episode` — change both), events/steps as `core/streaming.py` makes them (`events.rs`), automation runs around the turn (`automation.rs`, a port of `server/automation_runtime.py` — change both), board tasks (`board.rs`, a port of `server/task_board_runtime.py` and `tools/board.py` — change both) with notifications (`src/notify.rs`, a port of `core/notifications.py`). Anything else (other tools, gated tools) hands the turn to Python by clearing `runtime` + `payload.handoff`. Tested in `tests/test_edge_agent.py` and `tests/test_edge_loop.py` (both runtimes, one fake model, diffed).
- `src/budget.rs` ports `core/budget.py` (limits per run kind + `JARVIS_BUDGET_MAX_*`, throttled `budget_update`, one `budget_exceeded`). Trackers return the events; the caller emits them.
- `src/catalog.rs` compiles in `core/builtin_models.json` — rebuild after editing it.
- Run starts (`src/gql/start.rs`) write the rows + `Job` and send `wake`; Python creates the `TaskState` from the job.
