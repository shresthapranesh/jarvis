# edge/ — Rust edge in front of Python

Read `README.md` here before changing routing, the worker link, the supervisor, or porting an operation — it has the wire-format contracts and the porting checklist.

- Goal: move jarvis to Rust incrementally so it runs on old, low-RAM hardware. Order work by RAM saved; the kernel stays Python.
- The edge owns :8000: it serves ported GraphQL operations from SQLite, the SPA, the chat page's startup queries (`models`, `todos`, `browserAvailable`), and — while a Python worker is linked — subscriptions, `runningTasks`, stops and run triggers. Everything else is proxied to Python on :8001.
- **Python owns the schema** (`db/engine.py:_migrate`). A GraphQL type is ported whole or not at all.
- Every ported operation is diffed against Python by `tests/test_edge_parity.py`, `test_edge_runs.py`, `test_edge_start.py`, `test_edge_supervisor.py`, `test_edge_schedule.py`. Keep them passing; add to them when porting.
- **Supervisor**: with `JARVIS_WORKER_CMD` set the edge starts Python when a job or proxied request needs it and stops it after `JARVIS_WORKER_IDLE` seconds (default 300) with nothing running, queued, or held.
- **Kernels** (`src/kernels/`): the agent's `ipykernel` processes are the edge's — Jupyter wire protocol over ZMQ (pure-Rust `zeromq`, ipc). Python behind the edge runs `run_cell` through loopback `/internal/kernels/{run,shutdown}` (`core/kernels.py:EdgeKernels`), so a notebook outlives an idle-stopped worker. A port of `core/kernels.py` — a change is made in both; diffed in `tests/test_edge_kernels.py`.
- **Bots** (`src/bots/`): Telegram and Discord run here, not in Python — a message is `start_chat`, the reply follows the run mirror. Python behind the edge starts neither; the Python bots only run when Python stands alone, so a bot change is made in both. Tested against a fake chat service in `tests/test_edge_bots.py`.
- **Scheduler**: the edge fires every schedule. `src/cron.rs` ports APScheduler's `CronTrigger` (DST quirks included) — a change to `core/scheduler.py:_cron` must be made in both. `src/schedule.rs:dispatch` must stay a port of `dispatch_board_tasks`.
- **LLM layer** (`src/llm/`, phase 2b): v1 transcript types, a port of the history shaping and cache layout, and hand-written clients for Gemini, Ollama, Chat Completions (OpenRouter) and Responses (Meta). The agent loop's model calls (`src/agent/`); `--llm-shape` / `--llm-call` drive it alone. `shape.rs` ports `core/messages.py` + `core/context_cache.py`, `compact.rs` ports `apply_per_call_compaction`, `perf.rs` ports `core/perf.py` — a change there is made in both. Diffed against Python in `tests/test_edge_llm.py`.
- **Agent loop** (`src/agent/`, phase 2d; on unless `JARVIS_AGENT_RUNTIME=python`): the chat turns, automation runs and board tasks the edge can serve are queued with `jobs.runtime = 'edge'` (`route.rs`) and claimed here (`queue.rs`, Python's claim plus the runtime condition). Python never claims, reaps or sweeps an edge job; the supervisor ignores them. The loop (`turn.rs`) runs a turn here — prompt as `model_request_node` builds it (`prompt.rs`, a port: change both), `run_cell`, the todo tools, `remember`, `write_artifact` and the bound MCP tools (`tools.rs`, `artifacts.rs` — a port of `tools/artifacts.py`, change both; schemas exported from Python to `tools.json`), retrieval and embeddings (`retrieve.rs`/`embed.rs`, ports of `core/retrieval.py`, `search_memory`, `search_skills`, `search_episodes`, `upsert_memory` — change both; also behind the memory and skill writes in `src/gql/memory.rs` and `src/gql/settings_lists.rs`, ports of `mutations/memory.py` and `mutations/skill.py` + `core/skill_store.py`), summarizing compaction and episodes (`summarize.rs` + `llm/compact.rs`, ports of `maybe_compact`/`record_episode` — change both), events/steps as `core/streaming.py` makes them (`events.rs`), automation runs around the turn (`automation.rs`, a port of `server/automation_runtime.py` — change both), board tasks (`board.rs`, a port of `server/task_board_runtime.py` and `tools/board.py` — change both) with notifications (`src/notify.rs`, a port of `core/notifications.py`). Gated tools wait on their `approvals` row here (`src/approvals.rs`, a port of `core/tool_gate.py` + `core/approval.py` — change both), answered by the edge's `resolveApproval` (`src/gql/approval.rs`), which also runs approved deferred actions (`core/approvals.py:ACTIONS` — change both). Anything else (other tools) hands the turn to Python by clearing `runtime` + `payload.handoff`. Tested in `tests/test_edge_agent.py` and `tests/test_edge_loop.py` (both runtimes, one fake model, diffed).
- `src/budget.rs` ports `core/budget.py` (limits per run kind + `JARVIS_BUDGET_MAX_*`, throttled `budget_update`, one `budget_exceeded`). Trackers return the events; the caller emits them.
- **Board, conversation and automation writes** (`src/gql/board.rs`, `src/gql/conversation.rs`, `src/gql/automation.rs`): ports of `server/graphql/mutations/board_task.py` with `db/ops.py`'s board CRUD, `answer_board_task` / `stop_board_task`, `db/ops.py:delete_conversation`, and `mutations/automation.py` with the automation CRUD (schedules validated by `cron.rs`, the scheduler told to reload) — a change to either side is made in both; diffed in `tests/test_edge_parity.py`. `decomposeBoardTask` plans through `src/llm/` (a port of `decompose_board_task` + `_parse_decomposition` — change both), deferring to Python when `route::serves_board` says no; an agent's `deleteAutomation` (approval-gated) stays Python.
- **Settings** (`src/gql/settings.rs`): a port of `core/settings_admin.py` (`KNOWN_SETTINGS`, `validate`, `redact`, `apply_setting`'s notes) and the setting type/query/mutations — change both. The edge writes and applies every key (an `mcp.*` key reconnects the MCP servers); only invalid JSON for a json key defers. Python caches the embedding model, the catalog and the tool policy, so a linked worker is told over the link (`apply_setting` call). Diffed in `tests/test_edge_parity.py`.
- **Models and tools** (`src/gql/models.rs`, `src/gql/tools.rs`): the catalog writes (custom models, endpoints, default) port `mutations/models.py` + `db/ops.py`'s custom-model/endpoint rows; `tools`/`setToolPolicy` port `core/tool_policy.py` — change both. The SDK catalogue is `src/gql/sdk_tools.json`, exported from Python (`JARVIS_UPDATE_GOLDEN=1 uv run pytest tests/test_edge_parity.py -k catalogue`). Writes tell a linked worker (`settings::tell_worker`). `modelSync` is `src/discovery.rs` (a port of `core/model_discovery.py` — change both) with Bedrock's SigV4 and credential chain in `src/aws.rs`; diffed against Python over one fake provider server in `tests/test_edge_model_sync.py`.
- **Memory consolidation** (`src/consolidate/`): ports of `core/memory_consolidation.py` (item path only — Python always has an embedder), `core/project_memory_consolidation.py` and `core/text_dedupe.py` (with the slice of `difflib.SequenceMatcher` it uses) — change both. Behind `consolidateMemory`, `consolidateProjectMemory` and the scheduler's two sweeps; a model the edge doesn't call (`consolidate::served`) leaves them to Python. `--maintenance-run <task>` runs one sweep. Diffed in `tests/test_edge_loop.py`.
- **MCP** (`src/mcp/`): the servers are the edge's — config merge (`config.rs`), our own client over stdio / Streamable HTTP / HTTP+SSE / websocket (`session.rs` and the transports; one session per listing and per call, as the adapter does), the manager and the adapter's result and schema conversions (`mod.rs`), the GraphQL API (`src/gql/mcp.rs`), `always` tools bound in the agent loop and the `mcp_servers` prompt segment. A port of `core/mcp.py` + `mutations/mcp.py`/`queries/mcp.py` — change both. Python behind the edge has no MCP client: `core/mcp.py:EdgeMcp` reads `/internal/mcp/state` and calls `/internal/mcp/call`, and re-reads when told (`apply_setting` on `mcp.servers`). Diffed against real servers in `tests/test_edge_mcp.py`; turns in `tests/test_edge_loop.py`.
- `src/catalog.rs` compiles in `core/builtin_models.json` — rebuild after editing it.
- Run starts (`src/gql/start.rs`) write the rows + `Job` and send `wake`; Python creates the `TaskState` from the job.
