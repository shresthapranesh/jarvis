# edge/ — the jarvis server, in Rust

Read `README.md` here before changing the API, runs, the agent loop or a test hook — it has the wire-format contracts and what each module ports.

- Goal: jarvis on old, low-RAM hardware. This is the whole server and CLI; only the agent's notebook kernels run Python (`tools/`: the `jarvis` SDK, web and browser). The name is historical — it began as an edge in front of the Python server. Module docs that say "a port of `core/…`" name Python code that is gone; the behaviour they describe is this code's now.
- It owns :8000: GraphQL (`graphql.rs`, `gql/`; Strawberry's 400s in its words, introspection on), subscriptions, REST (`rest.rs`, `logs.rs`), `/ws/browser`, `/health`, and the SPA from `$JARVIS_APP_DIR/static/dist` (`web.rs`). `frontend/schema.graphql` is exported from it (`pnpm schema` → `--print-schema`).
- **The schema** (`src/schema.rs`): `schema.sql` makes a new database, `migrate` brings an older one up, at start and before CLI commands. A change goes in both; `tests/test_edge_schema.py` checks a migrated database has the fresh shape, and holds both to what Python made of them when the schema moved here (recorded — update the recording with the change).
- **Tests** (`tests/test_edge_*.py`) compare the binary with what Python answered, recorded before Python's server and runtime were deleted (`tests/python_golden.py`, `tests/golden/python/`). A deliberate change to an answer is an edit to the recording, said in the commit. Databases are seeded with `tests/seed.py`. `cargo test` for the unit tests.
- **Runs** (`runs.rs`, `gql/start.rs`, `gql/runs.rs`): a trigger writes the rows + `jobs` row, registers the run *before* the commit, then wakes the agent loop. Stops set the run's flag and the job's `cancel_requested`. `JARVIS_RUN_JOBS=0` queues without running (tests).
- **Agent loop** (`src/agent/`): claims every chat, automation, board-task and workflow job (`queue.rs`, Python's claim under the thread lease; legacy `runtime` values ignored). The turn (`turn.rs`) — prompt as `model_request_node` built it (`prompt.rs`; the static system prompt is `src/system_prompt.md`, compiled in), `run_cell`, the todo tools, `remember`, `write_artifact`, `spawn_workers` (`workers.rs`, a port of `tools/workers.py` + the roles in `core/agents.py`; workers' tools in `files.rs`/`artifacts.rs`, ports of `tools/files.py`/`tools/artifacts.py`), bound MCP tools, `run_workflow`. Bad tool arguments are answered for the model as `invoke_tool` worded Pydantic's errors (`tools::Args`, shared with the workers). Retrieval and embeddings (`retrieve.rs`/`embed.rs`, ports of `core/retrieval.py`, `search_memory`, `search_skills`, `search_episodes`, `upsert_memory`), summarizing and episodes (`summarize.rs` + `llm/compact.rs`), events/steps as `core/streaming.py` made them (`events.rs`), automations (`automation.rs`), board tasks (`board.rs`) with notifications (`src/notify.rs`), workflows (`workflow/`). A model it can't call, a prompt it can't build, or a run that can't start (`Agent::fail_start`) fails the run with the reason. At start, `recover` + `sweep.rs` (Python's startup sweeps; `--startup-sweep` runs just that). Tested in `tests/test_edge_agent.py` and `tests/test_edge_loop.py`.
- **Approvals** (`src/approvals.rs`, a port of `core/tool_gate.py` + `core/approval.py`): gated tools wait on their `approvals` row, answered by `resolveApproval` (`src/gql/approval.rs`), which also runs approved deferred actions. An agent's (`X-Jarvis-Caller: agent`) `deleteWorkflow` / `deleteSkill` / `deleteAutomation` / `callMcpTool` goes through `approval::gate_action` when `approval.required_actions` names it: recorded, an open duplicate reused, the mutation failing with "Approval required: …".
- `src/budget.rs` ports `core/budget.py`. Trackers return the events; the caller emits them.
- **Writes** (`src/gql/*`): ports of the Python resolvers and `db/ops.py` CRUD — board, conversations, automations (schedules validated by `cron.rs`, the scheduler told to reload), settings (`settings.rs`: `KNOWN_SETTINGS`, `validate`, `redact`; an `mcp.*` key reconnects the MCP servers), models and endpoints (`models.rs`), tool policy (`tools.rs`; the SDK catalogue is `src/gql/sdk_tools.json`, exported from `tools/sdk.py` — `JARVIS_UPDATE_GOLDEN=1 uv run pytest tests/test_edge_parity.py -k catalogue`), memory and skills (`searchMemory` is the SDK's `search_memory`). Errors Python's parsers worded are worded here, with the reason. Diffed in `tests/test_edge_parity.py`.
- **`modelSync`** is `src/discovery.rs` (a port of `core/model_discovery.py`) with Bedrock's SigV4 and credential chain in `src/aws.rs`. A listing it can't read skips that provider with the reason; diffed in `tests/test_edge_model_sync.py`.
- **Scheduler** (`schedule.rs`): every timer. `src/cron.rs` ports APScheduler's `CronTrigger` (DST quirks included), held to its recorded answers in `tests/test_edge_schedule.py`. `schedule.rs:dispatch` is a port of `dispatch_board_tasks`.
- **Memory consolidation** (`src/consolidate/`): ports of `core/memory_consolidation.py`, `core/project_memory_consolidation.py` and `tools/text_dedupe.py` (which the SDK still uses — change both). `--maintenance-run <task>` runs one sweep; compared with Python's recorded sweeps in `tests/test_edge_loop.py`.
- **LLM layer** (`src/llm/`): hand-written clients for Anthropic, Bedrock, Gemini, Ollama, Chat Completions (OpenRouter, endpoints) and Responses (Meta). `shape.rs` ports `core/messages.py` + `core/context_cache.py`, `compact.rs` `apply_per_call_compaction`, `perf.rs` `core/perf.py`; `transcript.rs` is the v1 record (`edge/transcript_format.md`). `--llm-shape` / `--llm-call` drive it alone; compared with LangChain's recorded requests and replies in `tests/test_edge_llm.py`.
- **Kernels** (`src/kernels/`): `ipykernel` processes over the Jupyter wire protocol (pure-Rust `zeromq`, ipc). A port of `core/kernels.py`; `--kernel-cells` drives them for `tests/test_edge_kernels.py`.
- **MCP** (`src/mcp/`): our own client over stdio / Streamable HTTP / HTTP+SSE / websocket, the manager, the GraphQL API (`src/gql/mcp.rs`), `always` tools bound in the loop. A port of `core/mcp.py` + the adapter; tested against real servers in `tests/test_edge_mcp.py`.
- **Browser** (`src/browser/`): `/ws/browser`, the live view (a port of `core/browser_stream.py` + `routes_browser.py` + `ensure_running`); tested against a fake DevTools browser in `tests/test_edge_browser.py`.
- **Bots** (`src/bots/`): Telegram and Discord; a message is `start_chat`, the reply follows the run. Tested against a fake chat service and the loop's fake model in `tests/test_edge_bots.py`.
- **Command line** (`src/cli/`): `jarvis-edge run|config|model|memory|start` (no command serves) — a port of `main.py`, compared with its recorded output in `tests/test_edge_cli.py`. `mcp add|list|get|remove` is the edge's own (`cli/mcp.rs`, `tests/test_edge_cli_mcp.py`): it writes `mcp.servers` as the MCP tab does, prints header/env values as `••••`, and tells a running server to reconnect.
- `src/catalog.rs` compiles in `src/builtin_models.json` (the first entry is the default model) — rebuild after editing it.
